# 사내 Luna·Terra에 순서대로 줄 작업

## 첫 지시문

사내 레포를 열고 다음 문장을 붙여넣는다. 승인된 사내 미러로 원본을 받는 환경이면 주소만 바꾼다.

```text
현재 열려 있는 사내 레포에 수율분석 하네스를 이식하려고 해. 먼저 https://github.com/dorothy90/map_agent.git 의 codex/goal-driven-harness 브랜치를 사내 레포 밖의 별도 폴더에 받아. 사내 레포의 원격 설정은 그대로 두고, 사내 자료는 외부로 보내지 마.

받은 브랜치에 앱 기준 커밋 58ad8ee7이 포함됐는지 확인하고, docs/yield-harness-port/START_HERE.md부터 읽어. 01-merge.md의 1~3절을 실행해서 FILES.tsv의 4,852개 파일을 검증한 다음 사내 레포와 비교해. 원본이나 설명서를 확인할 수 없으면 어느 단계에서 막혔는지 알려줘.

이번에는 비교까지만 해. Hermes 엔진, 전용 도구 6개, 백엔드, 기존 웹 프론트별로 추가할 파일 수·그대로 쓸 파일 수·충돌 수를 정리하고, 주요 충돌은 양쪽 경로와 이유를 보여줘. 사내 소스에 파일을 복사하거나 수정하기 전에 결과부터 보고해.
```

## 비교표 검토 후 사용할 지시문

| 차례 | 그대로 쓸 지시문 | 이 단계에서 받아야 할 것 |
|---|---|---|
| 1 | “먼저 engine/UPSTREAM.json의 고정 버전과 사내 엔진을 비교해. 같은 경로는 KEEP, 새 경로는 ADD 후보, 다른 코드는 MERGE 후보로 표시해. 공용 모듈과 잠금 파일은 목적지도 확인해. 필수 파일 중 보류한 항목마다 이유를 적어.” | 엔진 핀, 공용 코드·잠금 파일 결정과 근거 |
| 2 | “02의 도구 여섯 개를 등록 함수에서 구현까지 따라가. 사내 DB 연결·인증·사용자별 저장소와 겹치는 파일은 기존 동작과 가져올 계약을 함께 적어. 검토된 ADD만 복사하고 충돌 파일은 한 개씩 병합해.” | 여섯 도구의 구현·등록 경로, 충돌별 diff, 보존한 사내 기능 |
| 3 | “기존 harness_console의 main.tsx부터 세션·채팅·결과 화면까지 실제 import를 따라가. UI·스타일·잠금 파일·관련 테스트의 사내 목적지를 확인해. 설계 변경 없이 검토된 파일을 같은 구조로 옮겨.” | 웹 소스 경로, 진입점, 대응하는 테스트 목록 |
| 4 | “업무 스킬까지 옮길 범위면 profile-seed의 스킬 네 개를 03의 사용자별 경로와 대응해. 개인 메모·채팅은 별도 요청된 범위만 처리해. 같은 이름의 사내 스킬과 내용이 다르면 덮어쓰지 말고 차이를 보여줘.” | 스킬별 목적지, 충돌·보류된 내용 |
| 5 | “04의 ADD/KEEP 해시와 실행 비트를 다시 검사해. MERGE/HOLD와 체크포인트의 삭제 6개를 따로 대조해. 내부에서 확인한 결과, 미완료 항목, 사내 커밋을 분리해 보고해.” | 최종 파일 검수표. 이미 실행 가능한 경우 업무 검증 결과를 추가 |

단계마다 아래 한 줄을 사내 작업 기록에 남긴다. 다음 담당자가 MERGE와 HOLD의 이유를 이어서 확인할 수 있게 구체적인 상대경로를 쓴다.

```text
단계 | 사내 기준 커밋 | 원본 경로 → 내부 경로 | 결정 | 결정 근거/확인 결과 | 미완료 항목
```
