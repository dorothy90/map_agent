# 사내 레포에 기존 수율 분석 하네스 파일 옮기기

[GitHub 작업 브랜치](https://github.com/dorothy90/map_agent/tree/codex/goal-driven-harness)에서 **소스와 이 설명서**를 함께 받는다. 앱 소스 기준은 macOS 자동 검사와 Ubuntu 배포 전 검증을 포함한 `codex/goal-driven-harness`의 `725e4433e30d34f3c6f7cbc8f0fdb93b83803f2f`다. 현재 화면은 `harness_console`, 일반 채팅 실행은 `stock_chat`, Hermes 원본은 `5894e750c3dba980d43b25aa29e3958149ba2c61`이다. 사내 레포 정보와 내부에서 만든 비교표·diff·로그는 사내에만 둔다.

## 사내에서 시작하기

1. Luna 또는 Terra에서 **대상 사내 레포**를 작업 폴더로 열고 [첫 지시문](05-luna-terra.md)을 붙여넣는다.
2. [소스 병합 1~3절](01-merge.md)에 따라 GitHub 브랜치를 사내 레포 밖에 복제한다. 기준 커밋이 포함됐는지, 목록에 든 파일들이 맞는지 확인한 다음 사내 레포와 비교한다. 직접 GitHub 접근이 제한된 곳은 같은 브랜치와 커밋을 제공하는 사내 반입 미러 주소를 쓴다.
3. 첫 결과는 새 파일·동일 파일·충돌 파일 수와 주요 충돌 사유다. 복사와 수동 병합은 이 비교표를 검토한 다음 4절부터 진행한다. Git과 Python 3.11 이상이면 첫 비교를 실행할 수 있다.
4. 이식 검수는 [04](04-acceptance.md), 업무 스킬과 선택 데이터는 [03](03-runtime-data.md)을 따른다. 파일 검색은 로컬 체크아웃의 `docs/yield-harness-port/FILES.tsv`에서 경로나 기능명으로 할 수 있다. TSV는 UTF-8 탭 구분이다.

## 수량을 읽는 법

4,854개는 Git 이력 전체도, 우리가 새로 작성한 파일 수도 아니다. 고정 원본과 현재 기능을 보존할 소스·관련 테스트·운영 참조의 파일 수다. `required` 4,014개에는 통째로 동일성을 확인해야 하는 Hermes 고정 번들이 포함된다. `test` 813개, `optional` 15개, `docs` 12개는 설치 의무와 구분해 표시했다. 발췌된 체크포인트 목록만 복사하면 예전 커밋에 있던 업무 코드가 빠진다.

[반입 전 실제 검증 기록](VERIFICATION.md)에 기준 소스 무결성, 사내 충돌 모의 병합, 원본 스킬, 예시 DB에서의 실제 업무 결과를 적었다. 사내 담당자가 내린 병합 판단과 확인 결과는 외부로 보낼 필요가 없다.
